## 1. Descripción del alcance

Este pase incorpora la parametrización de la ruta de archivos de log del sistema. La ruta y la retención de logs dejan de estar fijas en el código y pasan a ser configurables desde `appsettings.json`, sin necesidad de recompilar la aplicación.

### Cambios incluidos

| Componente | Tipo de cambio | Descripción |
|---|---|---|
| Binarios de la aplicación | Actualización | Se reemplazan los DLL compilados con el build de este alcance |
| `appsettings.json` | Configuración nueva | Se agrega la sección `SerilogSettings` con la ruta de logs y días de retención.  Se agrega la sección `DataProtection` con la ruta de almacenamiento de keys |
| `Program.cs` | Corrección | Se agrega configuración de Data Protection para persistir keys de antiforgery en disco |

### Archivos entregados

| Archivo | Contenido |
|---|---|
| `datahub_alcace_1.zip` | Binarios compilados de la aplicación |

## 5. Actualizar appsettings.json

Este paso agrega la nueva sección de configuración de logs al archivo existente. **No reemplaza el archivo completo.**

### 6.1 Abrir el archivo de configuración

```powershell
notepad "C:\Sitios\DataSmartHub\appsettings.json"
```

### 6.2 Agregar la sección SerilogSettings

Localice la llave `"AllowedHosts"` en el archivo. Agregue el bloque siguiente **inmediatamente después** de esa propiedad, antes del cierre del JSON:

```json
"SerilogSettings": {
  "LogPath": "Logs/log-SDH-.txt",
  "RetainedFileCountLimit": 30
}
```

**Ejemplo de la sección en contexto dentro del archivo:**

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "ENC:..."
  },
  "Logging": { ... },
  "AllowedHosts": "*",
  "SerilogSettings": {
    "LogPath": "Logs/log-.txt",
    "RetainedFileCountLimit": 30
  },
  "JwtSettings": { ... },
  ...
}
```

| Propiedad | Descripción | Valor recomendado producción |
|---|---|---|
| `LogPath` | Ruta y nombre del archivo de log. Acepta ruta relativa o absoluta. | `"Logs/log-SDH-.txt"` (relativa a la raíz del sitio) |
| `RetainedFileCountLimit` | Cantidad de archivos de log diarios que se conservan. | `30` |

**Personalizar el nombre del archivo de log:**

El nombre del archivo se puede ajustar segun el estandar de nombrado de la organizacion. Serilog agrega automaticamente la fecha al nombre antes de la extension. El prefijo antes del guion final es la parte configurable:

```
"LogPath": "Logs/<prefijo>-.txt"
                   ^^^^^^^^
                   Esta parte se personaliza
```

Ejemplos segun convenciones comunes:

| Estandar | Valor de LogPath | Archivo generado |
|---|---|---|
| Por aplicacion | `"Logs/log-SDH-.txt"` | `log-SDH-20260618.txt` |
| Por sistema | `"Logs/DataSmartHub-.txt"` | `DataSmartHub-20260618.txt` |
| Generico | `"Logs/log-.txt"` | `log-20260618.txt` |

**Ruta relativa** — los logs se generan dentro de la carpeta del sitio:
```
C:\Sitios\DataSmartHub\Logs\log-SDH-20260618.txt
```

**Ruta absoluta** — ejemplo si se requiere centralizar logs fuera del sitio:
```json
"LogPath": "D:/Logs/DataSmartHub/log-SDH-.txt"
```

### 6.3 Actualizar RoleGroupMappings en LdapSettings

Dentro de la sección `"LdapSettings"` > `"RoleGroupMappings"`, actualice los valores de `SUPERVISOR` y `CONSULTA`:

**Valor anterior:**

```json
"RoleGroupMappings": {
  "ADMIN": "GS_DSH_SUPAD",
  "SUPERVISOR": "GS_DSH_AUDIT",
  "AGENTE": "GS_DSH_USER",
  "CONSULTA": "Gs_DSH_AUDIT"
}
```

**Valor nuevo:**

```json
"RoleGroupMappings": {
  "ADMIN": "GS_DSH_SUPAD",
  "SUPERVISOR": "GS_DSH_SUPERVISOR",
  "AGENTE": "GS_DSH_USER",
  "CONSULTA": "GS_DSH_AUDIT"
}
```

> **Requisito previo:** El grupo `GS_DSH_SUPERVISOR` debe existir en Active Directory antes de aplicar este cambio. Coordine con el equipo de infraestructura su creacion.

### 6.4 Agregar la seccion DataProtection

Localice la sección `"SeedSettings"` en el archivo. Agregue el bloque siguiente **inmediatamente antes** de `"LdapSettings"`:

```json
"DataProtection": {
  "KeysPath": "DataProtection-Keys"
}
```

**Ejemplo de la sección en contexto dentro del archivo:**

```json
{
  ...
  "SeedSettings": { ... },
  "DataProtection": {
    "KeysPath": "DataProtection-Keys"
  },
  "LdapSettings": { ... }
}
```

| Propiedad | Descripción | Valor recomendado producción |
|---|---|---|
| `KeysPath` | Ruta donde se persisten las keys de Data Protection. Acepta ruta relativa o absoluta. | `"DataProtection-Keys"` (relativa a la raíz del sitio) |

**Ruta relativa** — las keys se almacenan dentro de la carpeta del sitio:
```
C:\Sitios\DataSmartHub\DataProtection-Keys\
```

**Ruta absoluta** — ejemplo si se requiere centralizar fuera del sitio:
```json
"KeysPath": "D:/DataProtection/SmartDataHub"
```

> **Importante:** La carpeta se crea automaticamente si no existe. Esta carpeta **no debe eliminarse** entre deployments. Si se elimina, los tokens de antiforgery y cookies activas se invalidan y los usuarios deberan iniciar sesion nuevamente.

### 6.5 Validar el JSON

Antes de guardar, verifique que el archivo JSON es válido. Puede pegarlo en un validador en línea o ejecutar desde PowerShell:

```powershell
Get-Content "C:\Sitios\DataSmartHub\appsettings.json" | ConvertFrom-Json
```

Si el comando no lanza error, el JSON es válido. Guarde y cierre el archivo.

## 6. Iniciar el sitio en IIS

### 7.1 Iniciar el sitio

1. En el **Administrador de IIS**, haga clic derecho sobre **`Data Smart Hub`** y seleccione **"Iniciar"**.

Alternativamente, desde PowerShell:

```powershell
Start-WebSite -Name "Data Smart Hub"
```

### 7.2 Reiniciar el grupo de aplicaciones

Para asegurar que el proceso worker cargue los nuevos binarios correctamente:

```powershell
Restart-WebAppPool -Name "SmartHubPool"
```

### 7.3 Verificar el estado

```powershell
Get-WebSite -Name "Data Smart Hub" | Select-Object Name, State
Get-WebAppPoolState -Name "SmartHubPool"
```

Ambos deben mostrar el estado **`Started`**.

## 8. Plan de rollback

Si la verificación falla, ejecute los siguientes pasos para restaurar el estado anterior.

### 9.1 Detener el sitio

```powershell
Stop-WebSite -Name "Data Smart Hub"
```

### 9.2 Restaurar los binarios anteriores

```powershell
# Eliminar contenido actual (excepto appsettings.json)
Get-ChildItem "C:\Sitios\DataSmartHub\" -Exclude "appsettings.json" | Remove-Item -Recurse -Force

# Copiar el respaldo sobre la carpeta del sitio
Copy-Item "C:\Respaldos\DataSmartHub_20260618\*" `
          "C:\Sitios\DataSmartHub\" -Recurse -Force
```

### 9.3 Restaurar appsettings.json

```powershell
Copy-Item "C:\Sitios\DataSmartHub\appsettings.json.bak_20260618" `
          "C:\Sitios\DataSmartHub\appsettings.json" -Force
```

### 9.4 Reiniciar el sitio

```powershell
Start-WebSite -Name "Data Smart Hub"
Restart-WebAppPool -Name "SmartHubPool"
```
